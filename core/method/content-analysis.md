# Method Pack: Content Analysis (analisis isi pemberitaan/dokumen)

Lapis 3 — Method Pack. Isi dari v2 (Content Analysis Pack).

## Kapan cocok / tidak cocok
- Cocok: memetakan pemberitaan (jumlah, tone, jenis media, framing, sumber berita); data awal Bab I; triangulasi.
- Tidak cocok: mengukur sikap atau persepsi khalayak secara langsung.

## 8 langkah
| Langkah | Isi | Gate manusia |
|---|---|---|
| 1. Fit | Method Fit Advisor (core) | Mahasiswa + pembimbing |
| 2. Design | Unit analisis, kategori, periode | |
| 3. Instrument | Lembar koding + definisi kategori | Mahasiswa |
| 4. Plan | Sumber berita, kata kunci, kriteria inklusi, rencana uji reliabilitas | Masuk Bab III |
| 5. Pilot | Koding 20–30 berita, perbaiki definisi | |
| 6. Collect & QC | Kumpulkan (GDELT, RSS, arsip portal), hapus duplikat | |
| 7. Analyze | Statistik deskriptif dengan skrip/spreadsheet | |
| 8. Review & Interpret | Critic | Mahasiswa |

## Peran: content-coder

```text
PERAN: CONTENT CODER

Tugas: bantu koding berita/dokumen terlampir sesuai lembar koding di knowledge.

Aturan:
- Koding hanya berdasarkan teks terlampir. Untuk setiap keputusan kategori, kutip frasa pendukung dari teks.
- Jika kategori tidak jelas, tandai [RAGU] dan jelaskan dua kemungkinan; mahasiswa yang memutuskan.
- Jangan menghitung frekuensi atau persentase; mahasiswa menghitung di spreadsheet.

Output: tabel ID berita | Tanggal | Media | Kategori per variabel | Kutipan pendukung | [RAGU].
```

## Kriteria G4
Reliabilitas antar-pengkode Krippendorff α ≥0,80 (pengkode kedua = mahasiswa atau rekan, AI tidak dihitung sebagai pengkode); periode dan kriteria berita sesuai rencana.

## Alat
GDELT, RSS Google News, arsip portal berita, spreadsheet, skrip Python (pandas) untuk deskriptif.

## Tes penerimaan pack
Koding AI pada 30 berita dibandingkan dengan koding mahasiswa; daftar ketidaksesuaian dipakai memperbaiki definisi kategori.
